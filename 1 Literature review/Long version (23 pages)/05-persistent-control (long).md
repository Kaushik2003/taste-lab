# 6. Changes that persist in the weights

Most control in language models is temporary: a prompt, a sampling choice, or a steering vector added during one run. Persistent control writes the change into the weights, so it lasts. This section asks four questions. By which routes can the weights of a deployed model change? Who chooses the change? Who decides whether it stays? And what happens when a model changes again and again?

Two routes exist. The first builds the ability to change into the architecture and trains it; we call it learned memory. The second leaves the architecture alone and writes small changes straight into the weights of an ordinary pretrained model; we call these direct edits. The routes come from different research groups, and papers almost never compare them.

The main finding has two parts. Weights can change by both routes. And where the model's own judgment decides which change stays, that judgment is its certainty or a verbal score under a human rubric; no method uses an evaluation signal read from the model's hidden states, and every direct edit is decided by an outside score. No study on either route checks what a change does to the model's preferences.

## 6.1 Route one: learned memory

The idea that a system rewrites itself is old. Schmidhuber's Gödel machine was a theoretical design for a program that rewrites its own code once it has proved that the rewrite is useful [@Schmidhuber 2003]. Early neural versions changed their own weights by a learned rule. A self-referential weight matrix produced, at each step, its own key, query, and learning rate, and added a small update to itself; gradient descent learned only its starting state ([[SRWM - a weight matrix that rewrites itself (Irie 2022)]]). A related network produced a signal that set how fast its own plastic connections changed ([[Backpropamine - a network sets its own plasticity (Miconi 2019)]]). Test-time training updated a model on each test input with a self-supervised task [@Sun 2019]. These systems changed themselves at run time by a rule that training had fixed. No judgment of good or bad entered the loop.

Recent work scales the idea to language models. Titans added a memory module that updated its own weights during use. Surprise drove the update: the memory wrote more strongly the inputs that it predicted badly, with a momentum term and a forgetting gate ([[Titans - a memory that learns from surprise at test time (Behrouz 2025)]]). Nested Learning generalized the design. It treated a model as a chain of memory blocks that update at different rates, fast blocks for short-term memory and slow blocks for long-term knowledge, and its demonstration model produced its own update targets and learning rates ([[Nested Learning - a model that learns its own update rule (Behrouz 2025)]]). The authors compared a standard deployed model to a patient who cannot form new long-term memories, and they stated that catastrophic forgetting is "not solved in general".

Sleep, the latest step, moved short-term memory into long-term weights in an offline phase ([[Sleep - a model consolidates memories into its weights (Behrouz 2026)]]). During "sleep" the model first switched on a small new block of weights in a slower memory and trained only that block to reproduce what the faster memory had learned. Then it "dreamed": it wrote synthetic training examples, kept the most promising by a gradient-based score, fine-tuned a copy of itself on each, and rewarded the examples whose copy scored better on an outside task. The method ran on ordinary pretrained models of 1B to 8B with small added blocks. Its results were positive and modest. On three maths benchmarks with an 8B model it scored 79.2, 69.0, and 46.1, against 76.6, 67.4, and 45.1 for the best other method. On learning new facts it scored 48.9 against 46.7 for the strongest earlier method, and 35.7 with dreaming removed. Three limits matter for this review: every update was gradient training; outside task scores decided which dreams counted; and "continual" meant two tasks learned in sequence, not a long run of sleep cycles. The tables gave no error bars.

## 6.2 Route two: direct edits of a known direction

Direct editing of weights began with facts. ROME located a fact in one layer and rewrote it with a rank-one edit, the smallest structured change to a weight matrix, and MEMIT extended the method to thousands of facts [@Meng 2022a; @Meng 2022b]. Task arithmetic showed that the difference between fine-tuned and original weights can be added to or subtracted from a model to add or remove a skill [@Ilharco 2022]. A parallel line steered behavior without touching the weights, by adding a direction to the hidden states during generation [@Turner 2023; @Panickssery 2023; @Zou 2023]. The work reviewed here joins the two lines: it takes a direction found by steering and writes it into the weights.

Four studies show what such edits can do. Removal can be exact: one direction carried refusal in 13 open chat models, and projecting it out of every matrix that writes into the main hidden path gave the same result as removing it during each run ([[One direction controls refusal (Arditi 2024)]]). General benchmarks mostly stayed within their error bands, but one truthfulness benchmark dropped in every model. Removal can be local: in distilled reasoning models, projecting a reasoning-length direction out of about 4% of attention heads fixed reasoning that was too short and raised one model's score on a maths benchmark from 82.3 to 89.4 ([[ThinkEdit - edit weights to think longer (Sun 2025)]]). Addition needs only forward passes: a method that turned a steering vector into one rank-one edit per attention output matrix raised a sycophancy score from 3.6 to 94.6, more than steering alone (63.9), with general knowledge within 0.15 points of the base model ([[TFTV - turn a steering vector into a weight edit (Perin 2026)]]). Those edits changed 6 to 17 layers, needed tuning per trait with an outside judge, and sat near the point where fluency broke. And edits can be sparse: editing only the heads and neurons best aligned with a steering vector beat steering at matched utility, although utility still fell against the base model, from 87.8 to 77.3 in one case ([[Steer2Edit - steering into small weight edits (Sun 2026)]]).

In all four, the authors chose the direction through contrast sets, labels, or a judge. The edits also suit behaviors that are close to on-or-off, such as refusal, better than graded qualities; this is our reading of the limits the papers state.

Direct edits have side effects on disposition. Fafuła compared two model families before and after removal of the refusal direction, on a task that contained nothing to refuse. Over 21,600 stock decisions, the edited models chose the optimistic option more often (by 12.2 and 7.4 percentage points), wrote longer justifications with fewer doubt words, and moved their stated confidence in opposite directions in the two families ([[One weight edit shifts a model's disposition (Fafuła 2026)]]). The study used one edit method, one task, and one language, and its author named the missing work: a broad battery of preferences, a second edit method, and a mechanism.

## 6.3 Route two, continued: weight-space programming

A different kind of direct edit lets a strong model read weights and write changes by reasoning. In the original report, a frontier model edited about 0.016% of the weights of a 0.8B model and raised its score on a maths benchmark from 7.9% to 48.1%, mostly by stopping repetitive reasoning loops ([[WSP - a model reads and edits weights (Takehi 2026)]]). The low starting score was itself a loop effect: 93% of the base model's answers hit the token limit. The method struggled when a fault was spread across the network.

Follow-up work has qualified the result in four ways. First, the key edit was simple. It acted like a nearly constant push along one direction, and a sort over eight low-variance neurons gave the same result, 67.0% against 67.4% ([[A simple sort replaces the anti-loop edit (Fischetti 2026)]]). A plain discrete optimizer found a better repair than the agent, 54.6% against 51.7% under one protocol, with four forward-pass requests, no language-model tokens, and about $0.90 of GPU time, where the agent had used 89.7 million tokens ([[A cheap optimizer beats the agent's weight repair (Salloum 2026)]]; abstract only). Second, replication was uneven. On two model sizes, held-out gains reached 29.5 points from changing 1,023 values, but 6 of 16 runs kept the original weights because the procedure could confirm no edit, and gains were smaller on the larger model ([[Exploring WSP - small weight edits, uneven results (Hu 2026)]]). Third, patching mostly failed under strict audits. On 42 audited tasks with metered forward passes, the best fully tested agent scored 0.535 overall and 0.404 on fixing networks ([[WeightBench - models cannot yet patch models (Marasini 2026)]]); these scores are lower bounds, because flagged runs counted as zero until reviewed. Fourth, two reports found the edits shallow: one model's edits acted at the output, through sampling temperature and one token, and the weights that models could read were mostly those of the input layer ([[Claude's WSP edits act at the output (Kundu 2026)]], [[Reading weights is mostly reading inputs (Goworek 2026)]]; both abstract only). On the positive side, a frozen language model wrote "weight programs" that installed a new skill in small vision and control networks, and the same program worked on independently trained copies, keeping 83 to 110% of the gain ([[WeightCode - a model writes programs that edit weights (Li 2026)]]). The goal and the task knowledge came from the experimenter.

One model has edited itself. Fan and colleagues gave an open 27B model its own weights, its graded answers on practice problems, and tools to run itself and read its hidden states, and they blocked gradients ([[A model rewrites its own weights (Fan 2026)]]). The model found that its wrong answers mostly ran out of tokens in loops. It took the difference between the mean hidden states of answers that finished and answers that did not, and removed 5% of that direction from two matrices of one layer. On 490 held-out problems accuracy rose from 57.2% to 61.3% and 63.8% in two sessions. In 5 of 8 sessions the model withdrew its edit after testing it. Smaller models of the same family failed: the 2B model made no edit, and the 4B and 9B models broke themselves. Three limits apply. Graded answers decided which edit the model kept. The gain was again a loop fix. And each session started from the original weights; the paper's abstract says that each edit improved on the last, but the body states that no session built on an earlier one, which the authors called "a first step toward" recursive self-improvement.

## 6.4 Self-directed training, and self-improvement that leaves the weights alone

SEAL let a model write its own fine-tuning data and settings, and reinforcement learning rewarded the self-written edits that improved a downstream score after the update ([[SEAL - models write their own training data (Zweiger 2025)]]). It handles change that is spread over the network, which direct edits do not. Each step needed an inner fine-tune, the authors reported forgetting across many edits, and the headline result was narrow: eight selected puzzle tasks on a 1B model.

Much recent "recursive self-improvement" does not touch the base weights at all. A self-taught optimizer improved the program that called the language model, not the model [@Zelikman 2023], and the Darwin Gödel Machine evolved an archive of agents that rewrote their own code and kept the variants that scored better on coding benchmarks [@Zhang 2025b]. Models rewrote their own system prompts in a loop ([[Self-modifying prompts keep the same core values (Stroganov 2026)]]). A frozen model edited its own prompts, skills, and memory behind a gate that accepted only net improvements ([[GUARD - a gate stops self-edits from breaking things (Zhang 2026)]]). Other systems refined a store of skills and memories, alternated workflow search with fine-tuning on their own outputs, or ran rounds of data selection and training [@Zhu 2026; @Lee 2026; @Wang 2026]. Sections 7 and 8 return to what these loops do to reliability and to values.

## 6.5 Who proposes the change, and who decides whether it stays?

Table 2 sorts the methods by two roles. Two recent surveys of self-improving systems sort by similar axes, the target of the update and the signal that drives it [@Ren 2026; @Yang 2026]. Table 2 adds the direct-edit methods and separates the proposer from the decider.

**Table 2.** Methods that change weights, by who proposes a change and what decides whether it stays.

| Method | Who proposes the change | What decides whether it stays | Gradients |
|---|---|---|---|
| Learned memory (Titans, Nested Learning) | A learned rule driven by surprise | Nothing; the rule always applies | Yes, at run time |
| Sleep | The model writes its own training examples | A gradient score, then an outside task score | Yes |
| SEAL | The model writes its own training data | An outside task score | Yes |
| Certainty as reward (INTUITOR) | The model's own outputs | The model's own certainty | Yes |
| Self-rewarding training | The model generates and ranks responses | The model's own verbal score, under a human-made rubric | Yes |
| Direction removal and steering-to-weights | The experimenter | Benchmarks and an outside judge | No |
| Weight-space programming | A larger outside model | A development-set score | No |
| Self-editing (Fan) | The model, from its own hidden states | The model's own tests on graded practice answers | No |

Three observations follow. First, proposing and deciding are separate roles, and different parties fill them in most methods. Second, the model's own judgment decides in two rows only, and in both the judgment is computed from the model's outputs: its certainty, or a verbal score. Section 7 shows that loops on exactly these two signals sharpen and drift. Third, no row uses an evaluation signal read from hidden states, of the kind described in Sections 5.1 and 5.2, and no gradient-free method uses the model's own judgment at all. The one self-editing model tested its own edit, but against answers that people had graded.

## 6.6 Cost, compared honestly

Papers often present direct edits as cheaper than training. The evidence is mixed. A direction edit needs only forward passes and a contrast set. But the agent that found the best-known weight repair used tens of millions of tokens, a plain optimizer then found a better repair for under a dollar, and each self-editing session took hours on a GPU. On the other side, Sleep cost four times more per step than plain fine-tuning and reached a given maths score in 3.6 to 4.8 times less wall-clock time. The real differences between the routes are not about cost. Direct edits need no training data and no new architecture, change very few values, and are open to inspection. Learned memory handles new knowledge and change that is spread over the network, and needs gradient updates and capacity set aside in advance.

## 6.7 Changes made again and again

A model that develops over time must survive many changes, and the evidence is thin on both routes. Direct edits pile up badly. When ROME and MEMIT made many edits to one model, the model forgot earlier edits and lost general ability, first slowly and then suddenly ([[Many sequential weight edits cause sudden forgetting (Gupta 2024)]]). Even a single edit could collapse a model, nearly all tested methods collapsed after a few edits on hard cases, and the change in perplexity after an edit served as a cheap warning sign ([[A few edits can collapse a model (Yang 2024)]]; abstract only). Later work traced the collapse to a growth loop in the size of the edited weights and reported a one-line fix that extended the usable number of edits more than four times [@Liu 2026b]. These studies edited facts, not behaviors. Nobody has run the self-editing model in sequence, because each of its sessions started from the original weights. Learned memory has run for two tasks: Sleep nearly kept its single-language score after learning two languages in sequence, where fine-tuning forgot, and its paper reports no long run. The one long run of self-judged training that we found decayed: a small model that fine-tuned itself each night on the attempts it judged good improved for about a week and then lost almost all of the gain ([[Self-judged nightly learning rises then decays (Kongsilp 2026)]]; Section 7.4).

## 6.8 Summary

Weights can change after deployment by two routes: learned memory inside a suitable architecture, with gradients, and direct edits of an ordinary model, without gradients. Direct edits work best for near on-or-off behaviors and for the repair of one local fault; under strict audits patching mostly fails, and a simple optimizer can replace the editing agent once the goal is known. One model has edited its own weights, at 27B only, for a small gain, with graded answers deciding, and with no edit building on an earlier one. Learned memory reports low forgetting and small gains over two sequential tasks, with outside scores deciding what stays. Direct edits change more than their target: one edit shifted two models' dispositions. For the loop of this review, the persist step exists in several forms. Where the model's own judgment decides what stays, it is certainty or a verbal score; a hidden-state evaluation signal decides in none. And after no change, on either route, has anyone measured a broad set of the model's preferences or asked the model what it had become.
